# Lichess — the product

Research date: 2026-09-08. Sources: https://lichess.org/features (WebFetch), https://lichess.org/faq (WebFetch + WebSearch), https://lichess.org/page/fair-play (WebFetch), and targeted WebSearch queries against lichess.org forum/blog pages and the GitHub API (`gh api`) against lichess-org repos, as cited inline.

## 1. What they do

**Play**
- Unlimited rated/casual games at six speed categories: UltraBullet, Bullet, Blitz, Rapid, Classical, Correspondence (source: https://lichess.org/features — mobile section explicitly lists all six; web section implies via "Correspondence chess with conditional premoves").
- Standard chess plus 8 variants: Chess960, Crazyhouse, Antichess, Atomic, Horde, King of the Hill, Racing Kings, Three-check (variant set confirmed structurally by `scalachess/core/src/main/scala/variant/`: `Antichess.scala`, `Atomic.scala`, `Chess960.scala`, `Crazyhouse.scala`, `FromPosition.scala`, `Horde.scala`, `KingOfTheHill.scala`, `RacingKings.scala`, `Standard.scala`, `ThreeCheck.scala` — 10 files because `Chess960`/`FromPosition`/`Standard` are base-game modes, not separate rule variants; `gh api repos/lichess-org/scalachess/contents/core/src/main/scala/variant`).
- Correspondence chess with **conditional premoves**: you play a hypothetical opponent reply on the analysis board, then register your own response to it; you can chain several plies and store multiple branches ("if X then Y, if Z then W") (source: WebSearch aggregating https://lichess.org/forum/lichess-feedback/conditional-premoves--how-do-they-work and related threads). Engines are banned even in correspondence; only "the Lichess opening explorer, plus any other chess books or opening databases" is allowed (source: https://lichess.org/page/fair-play).
- Simultaneous exhibitions ("simuls") — one host vs many players (source: https://lichess.org/features, module existence confirmed: `modules/simul`).
- Bot play against the built-in AI (Stockfish-backed) and against community-run bots via the Board/Bot API.

**Analysis**
- Free unlimited local (browser) engine analysis via the built-in Stockfish (WASM/NNUE), and a defined daily quota of **server-side deep analysis** — free accounts get 40 games/day (source: https://lichess.org/features, "Deep Stockfish 19 server analysis" line item).
- Unlimited cloud engine analysis: previously-computed evaluations are shared across users via a server-side cache (module: `modules/evalCache` — files `EvalCacheApi.scala`, `EvalCacheEntry.scala`; `gh api repos/lichess-org/lila/contents/modules/evalCache/src/main`).
- 7-piece Syzygy endgame tablebase lookups (source: https://lichess.org/features).
- Board editor, FEN/PGN import and export, move-by-move annotation with symbols (source: https://lichess.org/features; PGN handling confirmed by `scalachess/core/src/main/scala/format/pgn/`).

**Puzzles**
- A large tagged/rated puzzle database — 6,057,356 puzzles as of Aug 2026 (source: WebSearch citing https://database.lichess.org/ and https://huggingface.co/datasets/Lichess/chess-puzzles), each carrying a Glicko-2 difficulty rating (range ~545–3024) and a rating deviation, plus tactical theme tags and a popularity score (source: WebSearch aggregating https://lichess.org/forum/lichess-feedback/puzzle-rating-4 and the HuggingFace dataset README).
- Puzzles are generated automatically from real games (module: `modules/puzzle`), then classified by theme (`PuzzleTagger.scala`, `PuzzleTheme.scala`), difficulty (`PuzzleDifficulty.scala`), and "tier"/trustworthiness (`PuzzleTier.scala`, `PuzzleTrust.scala`) — `gh api repos/lichess-org/lila/contents/modules/puzzle/src/main`.
- Each solve attempt is itself treated as a **Glicko-2-rated game between the player and the puzzle**, so the player's puzzle rating and the puzzle's own difficulty co-evolve (source: WebSearch aggregating Lichess feedback forum discussion of puzzle rating).
- Three timed/gamified modes beyond single puzzles: **Streak** (`PuzzleStreak.scala`, chain of increasingly hard puzzles, one mistake ends the run), **Storm** (3-minute puzzle-count sprint), and **Racer** (`modules/racer`, multiplayer real-time puzzle race) (source: https://lichess.org/features + module list).
- `PuzzleDashboard.scala` and `PuzzleOpening.scala` provide per-user breakdowns by theme and by opening.

**Studies**
- Shareable, persistent, multi-chapter analysis notebooks with collaborative editing, comments, shapes/arrows, and PGN import per chapter (module: `modules/study`, files `Chapter.scala`, `ChapterMaker.scala`, `StudyMember.scala`, `StudyInvite.scala`, `PgnDump.scala`, `GifExport.scala`, `CommentParser.scala` — `gh api repos/lichess-org/lila/contents/modules/study/src/main`).
- Studies can export to PGN, animated GIF, and can pull positions from live/relayed games (`ExplorerGame.scala`, `GameToRoot.scala`).
- **Broadcasts** are a distinct but related feature (module: `modules/relay`) — real-time relay of over-the-board tournaments, pulling PGN feeds from tournament organizers/arbiters (`RelayFetch.scala`, `RelayPgnStream.scala`), enriching them with FIDE player data (`RelayFidePlayerApi.scala`), and rendering them as live studies with commentary support and team/board pairing views (`RelayGroup.scala`, `RelayRound.scala`, `RelayTour.scala`) — `gh api repos/lichess-org/lila/contents/modules/relay/src/main`.

**Insights**
- "Chess Insights": an analytics engine over a player's own analyzed games, built from four composable primitives — **metric, dimension, preset, filter** — combined into custom bar-graph/table reports (source: WebSearch aggregating https://lichess.org/@/lichess/blog/chess-insights/VmZbaigA and https://github.com/lichess-org/lila/discussions/11201).
- Tracked dimensions include move-time, game phase (opening/middlegame/endgame), material imbalance, opponent-strength bucket (Much weaker / Weaker / Similar / Stronger / Much Stronger), and rating gain (source: same WebSearch aggregation).
- Backing module `modules/insight`: `InsightDimension.scala`, `InsightMetric.scala`, `InsightPosition.scala`, `InsightRange.scala`, `AggregationPipeline.scala`, `PeersRatingRange.scala` (`gh api repos/lichess-org/lila/contents/modules/insight/src/main`) — the `AggregationPipeline`/`AggregationClusters` naming indicates this is built as MongoDB aggregation pipelines over indexed per-move analysis data (`InsightEntry`, `InsightIndexer`), populated incrementally whenever a user requests computer analysis of a game.

**Opening Explorer**
- A "global opening explorer" advertised at 6 billion games (source: https://lichess.org/features) served by a separate Rust service, `lila-openingexplorer`, with three independent databases: `/masters` (historical master games), `/lichess` (all rated Lichess games), `/player` (on-demand per-player opening stats) — see `07-data/opening-explorer.md` for full architecture.
- A **personal opening explorer**, filterable by color, rated/casual, speed, and date range, for your own games or (per the API) any player's games.

**Competitions**
- **Arena tournaments**: unlimited, continuous-pairing tournaments. Win = 2 points, draw = 1, loss = 0; a win-streak of 2+ doubles subsequent points until a non-win breaks it (flame icon shown); "Berserk" lets a player forfeit half their clock time in exchange for +1 point if they play ≥7 moves (increment is also cancelled on berserk, except 1+2 which becomes 1+0; berserk is unavailable at 0+1/0+2). Pairing is streamed/continuous — finish a game, get immediately repaired with someone near your current rank in the tournament, so you won't necessarily face every entrant (source: WebSearch aggregating https://lichess.org/tournament/help?system=arena, https://lichess.org/@/jmviz/blog/when-should-you-berserk/rQdcB4QB, and forum threads). Backing module `modules/tournament` — `AutoPairing.scala`, `Duel.scala`, `Revolution.scala` (pairing waves), `TournamentShield.scala`, `WaitingUsers.scala`, `arena/` subpackage — `gh api repos/lichess-org/lila/contents/modules/tournament/src/main`.
- **Swiss tournaments**: fixed number of rounds, official **FIDE Dutch pairing system**, implemented via the external `bbPairings` engine per the FIDE handbook — score groups split into top/bottom halves by pairing number and cross-paired; a full-point bye goes to whoever can't be paired in a round, and a player can only receive one bye per tournament; tiebreak is **Sonneborn–Berger** (sum of defeated opponents' scores + half the score of drawn opponents) (source: WebSearch aggregating https://lichess.org/swiss and FIDE Dutch-system pages). Backing module `modules/swiss` — `PairingSystem.scala`, `SwissTrf.scala` (Tournament Report File export, the FIDE-standard interchange format), `SwissScoring.scala`, `SwissBoard.scala` — `gh api repos/lichess-org/lila/contents/modules/swiss/src/main`.
- **Team battles** — teams compete inside an Arena, aggregating individual scores (`TeamBattle.scala` in the tournament module).

**Learning**
- Structured lessons in chess basics, unlimited "learn from your mistakes" review flows, and a **Practice** mode of curated positions/studies with defined goals per section (module `modules/practice` — `PracticeGoal.scala`, `PracticeSections.scala`, `PracticeStructure.scala`) — `gh api repos/lichess-org/lila/contents/modules/practice/src/main`.
- A "coordinate trainer" (module `modules/coordinate`) for square-naming speed drills.

**Community / social**
- Blog, forum (with a full-text search index — `modules/forumSearch`), teams (with team-scoped forums — `modules/team`, `teamSearch`), direct messaging (`modules/msg`), friend relations (`modules/relation`), and challenges.
- TV: spectate top-rated live games and streamers, aggregated across game types (`modules/tv`, `modules/streamer`).
- User blogging platform ("Ublog", `modules/ublog`).
- Titled-player verification (`modules/title`) and FIDE-linked identity (`modules/fide`).

**Customization / accessibility**
- Light/dark themes, multiple board and piece sets, custom backgrounds.
- Localized into 140+ languages on web, 100+ on mobile per the features page (source: https://lichess.org/features — note the discrepancy between the two figures on the same page; recorded verbatim, **NOT independently reconciled**).

**Mobile**
- Native iOS/Android apps (separate repo `lichess-org/mobile`, GPL-3.0 licensed — confirmed via `gh api repos/lichess-org/mobile/contents/LICENSE`), landscape support, same core feature set as web including analysis with a bundled Stockfish build (features page states "Stockfish 14+" for mobile vs "Stockfish 19" for web at the time of writing — version skew between platforms is real and dated, **treat exact version numbers as a snapshot, not a permanent fact**).

**Fair play**
- Rules page (https://lichess.org/page/fair-play) states what's banned: engines, opening books/tablebases during live games, move-suggestion extensions, and programmatic GUI interaction; programmatic play is only permitted through the official Board/Bot APIs. Correspondence is the sole exception allowing books/tablebases/the opening explorer.
- Detection is **two independent ML systems**, not one: **Irwin** (module `modules/irwin` in lila, engine repo `lichess-org/irwin`) does per-game engine-correlation analysis — comparing a player's moves against Stockfish's top choices/PVs across their games — and separately catches "reverse boarding" (identical move sequences in two games, one vs. AI, suggesting a human relayed the AI's moves into a real game) (source: WebSearch aggregating https://lichess.org/forum/general-chess-discussion/how-does-lichess-catch-cheaters and https://github.com/clarkerubber/irwin). **Kaladin** (separate repo `lichess-org/kaladin`, AGPL-3.0 confirmed via `gh api repos/lichess-org/kaladin` → `license.spdx_id`) is newer and complementary: a CNN trained on **Insights data** (avg. centipawn loss, move counts, etc.) that looks for play *uncharacteristic of the player themselves* rather than *characteristic of an engine* — and crucially doesn't require running Stockfish analysis on a game sample, so it can screen far more games/players (source: WebSearch aggregating https://github.com/lichess-org/kaladin and Lichess's own half-year update blog post). Automated action is reserved for clear-cut cases; everything else and every appeal goes to human moderators (`modules/report`, `modules/mod`).
- Auto-refund of rating for opponents of a confirmed cheater: "one minute after a player is marked, their 40 latest rated games in the last 5 days are taken" for adjustment (source: https://lichess.org/faq via WebSearch).
- Separate lightweight abuse control: `PlayerTitle`-unrelated **playban** (`modules/playban`) auto-restricts players who repeatedly abort/leave games; `FarmBoostDetection.scala` in `modules/round` suggests dedicated detection for rating-farming/sandbagging distinct from engine cheating (**NOT VERIFIED** in detail — filename only, no README read for this specific detector).

## 2. Why it works

- **Zero paywall on anything that affects fairness or core play.** Server analysis is quota-limited (40 games/day free), but local/cloud engine analysis, puzzles, tournaments, and studies are unlimited and free — so the free tier is not a stripped-down demo, it is the full competitive product. That removes "pay to get a real puzzle set / real analysis" resentment that plagues chess.com's free tier, and it is why Lichess wins on trust with the exact freelancer-adjacent, price-sensitive audience our own product targets.
- **One continuous, low-friction loop for the highest-frequency behavior (Arena).** Continuous pairing (no bracket waiting) plus Berserk/streaks gives instant, legible risk/reward decisions every single game — a session-retention mechanic bolted directly onto ordinary play rather than a separate minigame.
- **The opening explorer and insights turn "played chess" into a growing personal asset.** Every game you play adds to data you can query later (your own opening stats, your own performance dashboards). This is a strong retention hook: value compounds with usage instead of resetting each session.
- **Puzzles-as-a-market clears a real behavioral itch** (bite-sized, replayable, rated) with a rating system (Glicko-2 puzzle-vs-player) that makes difficulty self-calibrating without any manual curation cost.
- **Fair play is layered and cheap to keep improving**: two independently-trained detectors (behavior-based and engine-similarity-based) catch different cheater profiles, and both feed the same human moderation queue, so false positives get a human check before consequences land. This is the credibility backbone that lets the free/open model survive without a paid identity check.
- **Everything is engineered to be forkable/inspectable** (open source, engine-agnostic APIs) which builds a volunteer/contributor ecosystem Lichess does not have to pay for — translation (140+ languages), bots, third-party tools (Berserk API client, opening databases) all come from outside contributors because the platform is legible and MIT/AGPL-licensed at the boundaries that matter to them.

## 3. What they do badly

- **License fragmentation makes "just copy the good parts" impossible for anyone building a closed or differently-licensed product.** The board UI (chessground) is GPL-3.0-or-later, the server (lila) and websocket layer (lila-ws) and opening explorer are AGPL-3.0 — all strong copyleft. Only the pure chess-logic library (scalachess) is MIT. This is a genuine adoption cost for outside builders, not a minor footnote — see §9.
- **Feature sprawl is real.** 20 large content modules (tournament, swiss, study, relay, insight, puzzle, practice, coordinate, racer, storm, ...) is a lot of surface area for a new player to discover, and Lichess's own community has repeatedly asked "where do I find X" (source: forum thread titles surfaced during research, e.g. "where do I find this feature in lichess?"). A first-time user is not funnelled toward the small set of features that would hook them.
- **Insights and puzzle dashboards are buried and under-marketed.** They're genuinely rich (four-axis custom analytics) but discoverability is poor enough that dedicated third-party tools exist purely to re-surface the same underlying data more legibly (e.g. lumichess.com's "Chess Insights" competing product built essentially as a better front-end over the same idea).
- **Rating/identity has no cryptographic verifiability.** Every rating, every "played N games" claim, every puzzle-solve streak lives entirely inside Lichess's own MongoDB, asserted by the server. Nothing about a Lichess rating is independently checkable by a third party without trusting Lichess's API and Lichess's word for it (which is fine for Lichess's own trust model, but is exactly the gap a signed, recomputable rating exists to close).
- **Mobile trails web on engine strength** at time of research (Stockfish 14+ vs 19 per the features page) — an unreconciled version gap that suggests platform parity is not perfectly maintained.
- **No first-class payments/monetary layer at all** (by design — Lichess is donation-funded and explicitly ad-free/tracking-free). That's a strength for trust but means Lichess offers zero prior art for a chess app that must handle stakes, wagers, or payouts — the exact territory a Nimiq Mini App needs.

## 4. What we should copy conceptually

- **Free tier = full competitive product, not a demo.** Never gate correctness, fairness, or the core loop behind payment — gate only volume/compute-heavy extras (Lichess's model: unlimited local analysis, capped *server* analysis).
- **Continuous pairing over bracket-waiting** for casual/ladder-style play — minimize idle time between games.
- **Make risk legible and optional** (Berserk is literally "double or nothing on time for a point"): a single, well-understood lever a player can pull, not a menu of settings.
- **Compounding personal data as retention**: opening stats, performance dashboards, puzzle-rating history — value that grows the more you use the product and that you'd feel a loss leaving behind.
- **Two independent, cheap-to-run integrity signals rather than one expensive one** (Irwin's engine-correlation + Kaladin's behavior-anomaly) — defense in depth, and the cheaper signal (Kaladin, no engine run required) screens everyone while the expensive signal (Irwin) is reserved for flagged cases.
- **Everything programmatic goes through one narrow, official API surface** (Board/Bot), never ad hoc GUI automation — this is both an anti-cheat boundary and a clean integration story for third parties.
- **Structured tiebreak/pairing systems borrowed from real FIDE standards** (Dutch system, Sonneborn–Berger, TRF export) rather than inventing bespoke ones — instant credibility with the existing competitive chess audience.

## 5. What we can do better

- **A rating that is independently recomputable and cryptographically signed**, not merely API-readable. Lichess's rating is only as trustworthy as "trust Lichess's server." Our differentiator — sign each rated result, publish the update function, let anyone recompute — is something Lichess structurally cannot offer without a full architecture change, because its rating store (MongoDB, mutated server-side) is the source of truth by fiat, not by proof.
- **A drastically smaller, funnel-shaped feature set for a mobile-first Mini App**, where Lichess is deliberately broad. We are not competing with 20 modules; a focused core loop (play, verifiable rating, one or two hooks) is more legible than Lichess's admittedly sprawling menu — directly addressing the discoverability weakness noted in §3.
- **Native money-in-the-loop**, which Lichess deliberately has none of. Stakes/wagers resolved on verifiable, server-checked skill (never chance — this is a hard rule from `NIMIQ_OFFICIAL_RULES_PAGE_VERBATIM.md`) is uncharted territory Lichess's donation-funded model never had to solve, and it is the one place a Mini App can be strictly additive to what Lichess offers rather than a smaller copy of it.
- **Reuse Lichess's actual chess logic (scalachess, MIT) instead of reinventing move generation/PGN/FEN parsing**, while keeping our own product's presentation layer and rating logic fully original and MIT-clean — see §9 for exactly which pieces are safe to port.

## 6. What is technically required

To match table-stakes play (not the full platform):
- A correct chess rules engine: legal move generation, check/checkmate/stalemate, all special rules (castling, en passant, underpromotion, 50-move/threefold), ideally variant-ready. `scalachess` (MIT) is a directly reusable reference/port target — see the architecture file for module-level detail.
- A board UI with drag/drop, premove, last-move/check highlighting, and animation. `chessground` is the reference (interaction fidelity, exact premove-cancellation semantics), but it is GPL-3.0-or-later — **reference/observe only, do not port code** (see §9).
- A rating algorithm — Lichess uses Glicko-2 for players (`scalachess/rating/src/main/scala/glicko/GlickoCalculator.scala`) and even models puzzle-solving as a Glicko-2 "game" against the puzzle itself; Elo is also present (`Elo.scala`) for simpler contexts. Glicko-2's published algorithm (Mark Glickman, open academic paper) is implementable from spec without touching any Lichess code at all.
- A realtime transport for live games distinct from the web app server (Lichess: `lila-ws`, Redis pub/sub bridge to `lila`) — even a small app needs this separation once concurrency matters.
- A persistence layer for game history/insights if we want any analytics-style feature — Lichess uses MongoDB aggregation pipelines for Insights; any document store or even a well-indexed relational schema would serve a smaller app.

## 7. What could break

- **Copyleft contamination risk**: any accidental inclusion of chessground/lila/lila-ws/lila-openingexplorer source (even partial, even "just for reference while writing our own") into an MIT repo is a licensing incident, not a style nit — AGPL/GPL require derivative works to release full source under the same license, which is incompatible with our MIT positioning and with a closed submission process if that ever applied. Clean-room process (read, don't copy) is mandatory per project rules.
- **Rating-recomputation trust breaks if the signing key or the update function ever needs a silent patch.** Lichess can quietly tune Glicko-2 constants or ban/refund logic server-side with no user-visible commitment; a "cryptographically signed, independently recomputable" rating cannot quietly change its own math without either versioning the algorithm explicitly or breaking every historical proof. This needs a designed-in versioning scheme from day one.
- **Puzzle/opening-explorer-style data value compounds only at scale** — Lichess's numbers (6M puzzles, 6B opening-explorer games) are the product of a decade of a large user base; a new app cannot manufacture that data moat and must either bootstrap from public Lichess data dumps (available at database.lichess.org) or ship a materially different value prop that doesn't depend on data scale.
- **Fair play at small scale is asymmetric risk**: Lichess can afford false negatives because volume statistically buries them; a small app with real money at stake (wagers) cannot — a single successful engine-assisted win against a paying opponent is a trust-destroying event, not a rounding error.

## 8. What we can uniquely do because of Nimiq

- **On-chain-anchored, independently verifiable ratings**: sign each rated game result (moves + outcome + timestamp) and publish a recomputation function; anyone — not just us — can replay the signed history and arrive at the same rating, closing exactly the trust gap Lichess's server-owned rating has (§3, §5).
- **Native payment rails for stakes/wagers resolved on server-verified skill** (never chance, per the competition's own rules), settled instantly and feelessly on NIM for an audience (freelancers/casual players) that has zero patience for slow/costly settlement — something Lichess's ad-free/donation model never needed and chess.com's fiat rails can't do at this cost or speed.
- **No server-owned account as the root of identity** — a Nimiq wallet address *is* the identity, so "your rating" is portable and provable outside our own app entirely, unlike a Lichess username which only means anything inside lichess.org's database.
- **Device Identifier API** (per `NIMIQ_DEV_DOCS_FULL_REFERENCE.md`) gives us anonymous per-device handles without requiring a wallet for casual/first-touch users — a lighter-weight onboarding funnel than Lichess's own account creation, while still landing on a walleted, provable identity the moment money or a signed rating is involved.
